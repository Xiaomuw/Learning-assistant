## Maintenance responsibilities

The maintainer triages incoming issues, reviews contributions, checks security reports, coordinates dependencies and publishes releases when they are sufficiently verified.

Changes should be submitted via pull requests when practical. Larger architecture changes should be discussed through an issue first. The maintainer may request test evidence, source attribution or changes to reduce operational risk.

Only verified behavior should be described as production-ready, and releases should not be announced before required checks and intellectual-property reviews are complete.

This project has no advertised review or support service-level agreement. Governance can evolve if more maintainers join.
